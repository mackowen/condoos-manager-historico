## Achados da auditoria

| Severidade | Achado | Tratamento |
|---|---|---|
| Crítica | `SESSION_SECRET` usava fallback previsível `dev-secret-change-me`. | Removido; API exige variável com pelo menos 32 bytes e falha explicitamente sem ela. |
| Alta | CORS usava `cors()` sem allowlist. | Allowlist exata configurável por `CORS_ORIGINS`; origens não listadas recebem 403. Produção exige variável explícita. |
| Alta | Seed e `replit.md` expunham a senha fixa `condoos2026`. | Removida do código e da documentação; seed requer opt-in, ambiente dev/test e senha externa. |
| Alta | JWT persistido em `localStorage`, acessível a JavaScript da página. | Mantido para não criar fluxo híbrido; migração para cookie HttpOnly fica para campanha dedicada. |
| Média | Verificação JWT dependia do algoritmo implícito, aceitava payload sem validação de formato e tokens por 30 dias. | HS256 explícito, claims mínimos validados, `iat`/`exp` requeridos, validade máxima de 24h. |
| Média | API não aplicava headers de segurança Helmet e o handler padrão podia expor detalhes de erro. | Helmet adicionado; erros inesperados retornam resposta genérica e logam apenas o nome do erro. HSTS fica ativo em produção. |
| Baixa | O logger já redigia `Authorization`, cookies e `Set-Cookie`; serialização HTTP registrada não inclui headers. | Revisado e mantido; smoke confirmou ausência de token em logs observados. |

Login compara senha com bcrypt e retorna 401 genérico para credenciais inválidas. Não há cookie de autenticação; o cookie existente da interface guarda apenas preferência visual da sidebar. Nenhuma regra de RBAC, autorização de rota ou escopo tenant foi alterada.

## Alterações

- `artifacts/api-server/src/index.ts`: valida configuração de autenticação no startup.
- `artifacts/api-server/src/app.ts`: Helmet, allowlist CORS com defaults de loopback para desenvolvimento, exigência de `CORS_ORIGINS` em produção e resposta genérica para erros não tratados.

- `replit.md`: configuração documentada, credenciais demo removidas e risco de `localStorage` anotado como pendência.
- `.env.example`: exemplos sem segredo real. `.env.local` permanece ignorado, modo `600`; contém configuração somente local e não foi versionado.
- Nenhuma migration foi criada ou aplicada. Nenhuma chamada a `db:push`, `push-force` ou seed.
