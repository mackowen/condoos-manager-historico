## Auditoria e arquitetura

- Login e registro retornavam JWT no JSON; o AuthContext e o custom fetch persistiam `condo_token` em `localStorage` e enviavam Bearer. `/auth/me` exigia Bearer. O cliente usava Vite proxy local para `/api`; CORS já tinha allowlist de origens e Helmet.
- API Keys já eram enviadas por `X-API-Key`, validadas por hash, tenant e scopes pela implementação da 0008. O formulário de gestão de chaves lia Bearer de `localStorage`.
- A sessão web agora usa o JWT assinado somente no cookie `condo_session`, com `HttpOnly`, `Path=/api`, `SameSite=Lax`, validade de 24 horas e `Secure` quando `NODE_ENV=production`. Logout expira o cookie com os mesmos atributos. Login e registro não retornam JWT.
- `/auth/me` recupera usuário, condomínio, permissões atuais e um token CSRF. Esse token aleatório é autenticado por HMAC-SHA256 ligado ao JWT da sessão; o frontend o mantém somente em memória e nunca consegue derivar ou usar o JWT como credencial.
- `GET`, `HEAD` e `OPTIONS` não exigem CSRF. Mutação por cookie exige token válido e Origin/Referer autorizado. Login/registro exigem origem autorizada; logout é mutação autenticada e exige CSRF. API Key isolada não depende de CSRF; credenciais conflitantes são rejeitadas.
- CORS aceita credentials somente com origem exata allowlisted e inclui `X-CSRF-Token` no preflight. Produção exige `CORS_ORIGINS`; desenvolvimento mantém origens locais explicitamente listadas. Nenhuma alteração de schema/migration foi necessária.

## Testes adversariais e limpeza

- Pelo proxy real do Vite, registro criou cookie HttpOnly sem JWT no JSON; `/auth/me` funcionou; GET protegido passou sem CSRF; mutações sem token, com token inválido ou origem não autorizada retornaram 403; mutação com CSRF válido passou e ignorou `condominiumId` adulterado no body. Login também foi validado no modo de produção.
- RBAC permaneceu ativo: após reduzir temporariamente as permissões da role, leitura de units retornou 403. API Key com scope válido funcionou sem cookie/CSRF, não apareceu na listagem, foi rejeitada quando combinada com cookie e passou a retornar 401 após revogação.
- Logout expirou o cookie; `/auth/me` sem cookie retornou 401. Cookie malformado e JWT válido expirado também retornaram 401; Bearer não é aceito como fluxo web.
- Em execução `NODE_ENV=production`, o cookie incluiu `Secure` e `HttpOnly`; CORS refletiu somente a origem allowlisted com credentials e origem não autorizada recebeu 403. Preflight aceitou `X-CSRF-Token`.
- Health API direta e via proxy retornou 200; frontend retornou 200. Os processos foram encerrados. Dados temporários de registro, unidade, role, activity log e API Key foram removidos; consulta final confirmou `condoos_app`/`condoos` e zero linhas nas 25 tabelas públicas de aplicação. Nenhum seed foi executado.
- JWT, cookie, CSRF token, senha temporária e API Key não foram registrados nas evidências.
